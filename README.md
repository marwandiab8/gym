# gym

## Frontend build

The pages use a prebuilt Tailwind stylesheet (`public/tailwind.css`) and a service worker (`public/sw.js`) so the installed app opens fast and works offline. Both are generated by `scripts/build-assets.mjs`, which `firebase deploy --only hosting` runs automatically (`hosting.predeploy`). Run `npm install` once in the project root first, and `npm run build:assets` after changing markup or Tailwind classes if you want to preview the result without deploying.

## Exercise library (ExerciseDB) and machine photos

- **ExerciseDB** (free V1, https://oss.exercisedb.dev - non-commercial use, with credit) supplies exercise names, muscles, equipment, steps and an animation for each of its 1,500 exercises. `scripts/import-exercisedb.cjs <exercisedb.json> --write` loads them into Firestore `exercisedb/exdb_{id}` (for the exercise card) and writes `public/data/exercisedb-index.json` (for search). The animations load from ExerciseDB's own server. About 176 exercises are listed twice and one copy has no animation; `--check-gifs` finds them (results kept in `<exercisedb.json>.gifs.json`), and the index points each such copy at its twin (`sameAs`) so links and workouts made with it still show the animation.
- **Your exercises stay as they are.** Workout history, records, routines and "last sets" keep pointing at the original exercise ids (old `wger_*` catalog entries and custom exercises). Each one is linked to its ExerciseDB match in `users/{uid}/exercise_links/{exerciseId}` (`exdbId`, or null for no match; `matchedBy` is Claude's first guess - `match`, `close`, `none` - or `you`). Check and change links on `exercise-links.html`; `scripts/link-exercises.cjs` wrote the first guesses and never overwrites one marked `you`.
- **Search** lists your exercises first (under your names, matched on their ExerciseDB name too), then custom exercises, then ExerciseDB. An ExerciseDB exercise linked to one of yours is folded into yours, so picking it keeps the history. A new pick from ExerciseDB gets the id `exdb_{id}`.
- **Machine photos** (`machines.html`): photos are resized to 1,600 px in the browser, uploaded to Storage at `users/{uid}/machine-photos/`, and only then saved to `users/{uid}/machine_photos/{id}` as `untagged`; tagging sets the exercise. Tapping an exercise's name (in a workout, a workout's details, an exercise's records) opens a card with the machine photo, then the animation and steps.
- **Testing locally against the emulators:** `firebase emulators:start --only auth,firestore,storage --project gym-k2`, serve `public/` on localhost, and open a page with `?emulators=1`; `window.__testSignIn(email, password)` signs in a test user created in the auth emulator.

## AI coach (coach.html)

- **Ask any time** on the Coach page, or with **Ask the coach about this workout** in a workout's details (`coach.html#workout={id}&go=1` starts right away). Analyze one finished workout (the latest by default) or the last 4 weeks, with an optional question.
- `analyzeWorkout` (Gen1 callable, `us-central1`, the same `OPENAI_API_KEY` secret as the routine generator) reads your finished workouts and their heart rate. The coach is `COACH_MODEL` (GPT-6.1 Sol, a reasoning model, through OpenAI's Responses API, medium effort); if OpenAI refuses that request or its answer can't be used, `COACH_FALLBACK_MODEL` (gpt-4.1, Chat Completions) answers instead, and the analysis shows which model wrote it. `functions/lib/coachAnalysis.js` works out the facts - each exercise's sets, volume and estimated 1-rep max, its timing, its heart rate, the last time you did it, the days between workouts and how each lift moved - and holds the coach's instructions and reply check. The model only interprets the facts.
- **Timing is from when sets were logged** (an exercise's first and last logged set); sets have no times of their own. "Minutes per set" is the average time from one logged set to the next (rest plus the set); "minutes from previous exercise" runs from the previous exercise's last set to this one's first.
- Each analysis is saved in `users/{uid}/coachReports/{id}` (written only by the function; you can read yours). The coach has its own allowance: 10 an hour, 30 s apart (`_ai_rate_limits/{uid}_coach`).
